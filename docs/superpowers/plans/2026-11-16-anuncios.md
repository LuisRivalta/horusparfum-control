# Anúncios (Mercado Livre) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Módulo "Anúncios" no Horus: conectar a conta do Mercado Livre, montar e publicar os anúncios de um perfume (frasco + decants) com ficha, fotos, preço que preserva a margem depois das taxas, texto (com IA opcional), nota de qualidade e ligação dos anúncios que já existem no ML.

**Architecture:** Toda chamada à API do ML (que exige token) e à IA passa pelo backend FastAPI (`/api/mercadolivre/*`, `/api/anuncios/*`); tokens ficam numa tabela sem policy (só service role). Rascunhos, ficha, fotos e configuração ficam no Supabase e o frontend lê/grava direto, como no resto do Horus. Cálculos puros (custo do anúncio, título, fotos, checagens) ficam em `frontend/src/lib/anuncios.ts` com TDD; a busca do preço (que consulta taxas e frete no ML) fica em `backend/app/services/anuncios/preco.py` com TDD usando consultas falsas.

**Tech Stack:** React 19 + Vite + TS + Tailwind, vitest; FastAPI + httpx + supabase-py, unittest; SDK `anthropic` (Python) com `claude-haiku-5-5`; Supabase Postgres (SQL aplicado à mão).

**Spec:** `docs/superpowers/specs/2026-11-16-anuncios-design.md` (seções 3, 4 e 6). Fatos do ML conferidos em 16/11/2026 estão em "Fatos do ML" abaixo e valem mais que a seção 6.2 do spec onde divergem.

## Global Constraints

- Segredos (client secret do ML, access/refresh token, `ANTHROPIC_API_KEY`, service role) **só no backend**; nunca em resposta da API para o frontend nem em tabela legível por `authenticated`.
- SQL do Horus: o Luis aplica à mão no SQL Editor do projeto `wyobbztexoofhqdttxzq`. **Nunca** usar o MCP do Supabase (aponta para outro projeto).
- Git: trabalhar direto na `main`; commit por tarefa (só os arquivos da tarefa); **sem linha `Co-Authored-By`**; push só quando o Luis pedir.
- Dinheiro no frontend com `formatBRL()`; cálculo de dinheiro com `decimal.js` (frontend) e `Decimal` (backend).
- Depois de publicar, o Horus só mexe em **quantidade, preço (quando o Luis manda) e pausa/reativação**. Preço nunca muda sozinho.
- Categoria: `MLB6284`. Atributos obrigatórios: `BRAND`, `PERFUME_NAME`, `UNIT_VOLUME`. Decant sem código: `EMPTY_GTIN_REASON` = `17055160` ("o produto não tem código cadastrado").
- Máx. **12 fotos** por anúncio; título/`family_name` ≤ **150** caracteres; preço mínimo do ML **R$ 8**.
- Tipos de anúncio: `gold_special` = **Clássico**, `gold_pro` = **Premium**. A tela mostra os dois lado a lado.
- Preço final termina em **,90**.
- Margem é **sobre o custo** e tem de sobrar depois de comissão + taxa fixa + frete do vendedor: `preço − comissão − taxa_fixa − frete ≥ custo × (1 + margem)`.
- IA é opcional (liga/desliga na configuração); sem chave ou com falha, cai no modelo sem IA; a IA nunca publica.
- Backend é serverless (Vercel): nada de processo residente.
- Regra de auditoria da máquina: script novo (`.ps1`, `.py` avulso...) leva o sufixo `__Claude_Code_MS125_luisgfr` e é registrado; módulos do projeto (`backend/app/**.py`, `frontend/src/**.ts`) mantêm o nome, só o registro vale.

## Fatos do ML (conferidos em 16/11/2026, docs oficiais developers.mercadolivre.com.br)

- **OAuth:** autorização `https://auth.mercadolivre.com.br/authorization?response_type=code&client_id=..&redirect_uri=..&state=..`; token `POST https://api.mercadolibre.com/oauth/token` (form-urlencoded) com `grant_type=authorization_code` (+`client_id`, `client_secret`, `code`, `redirect_uri`) ou `grant_type=refresh_token` (+`client_id`, `client_secret`, `refresh_token`). Access token dura **6 h**; refresh token dura 6 meses e é **de uso único** (cada refresh devolve outro; só o último vale). `redirect_uri` idêntica à cadastrada, sem parâmetros (usar `state`). PKCE é opcional por app (não ativar).
- **User Products:** conta com a tag `user_product_seller` (em `GET /users/me` → `tags`) **não envia `title`**: envia `family_name` (≤ 150) e o ML gera o título. Conta sem a tag envia `title`. O Horus guarda um texto só (`titulo`) e manda no campo certo.
- **Criar:** `POST /items` com `family_name|title`, `category_id`, `price`, `currency_id: "BRL"`, `available_quantity`, `buying_mode: "buy_it_now"`, `condition: "new"`, `listing_type_id`, `pictures: [{source}]`, `attributes: [{id, value_name}|{id, value_id}]`, `shipping: {mode: "me2", free_shipping}`. Guardar `id`, `permalink`, `status`. Item pode virar `closed` minutos depois (duplicado/imagem): reconsultar.
- **Descrição:** depois de criar, `POST /items/{id}/description` com `{"plain_text": "..."}`. Emoji e `<` são rejeitados.
- **Taxas:** `GET /sites/MLB/listing_prices?price=&category_id=MLB6284&currency_id=BRL&listing_type_id=&logistic_type=drop_off&shipping_mode=me2` (exige token) → `sale_fee_amount`, `sale_fee_details.fixed_fee`, `sale_fee_details.percentage_fee`.
- **Frete do vendedor:** `GET /users/{user_id}/shipping_options/free?dimensions={A}x{L}x{C},{peso_g}&item_price=&listing_type_id=&mode=me2&condition=new&logistic_type=drop_off&free_shipping=true` (exige token) → `coverage.all_country.list_cost`. Regra MLB: produto novo **≥ R$ 79** tem frete grátis obrigatório e o vendedor paga (com desconto); **R$ 19 a R$ 78,99** o ML paga (custo do vendedor 0); **< R$ 19** frete grátis é opcional (o Horus publica sem frete grátis → custo 0).
- **Qualidade:** `GET /item/{id}/performance` → `score`, `level`, `level_wording`, `buckets[].variables[].rules[]{status, mode, wordings{title, label, link}}`.
- **Itens da conta:** `GET /users/{id}/items/search?limit=100&offset=` (até 1000; acima disso `search_type=scan` + `scroll_id`); detalhes em `GET /items/bulk?ids=A,B` (máx. 20 ids; o antigo `/items?ids=` foi descontinuado).
- **Atualizar:** `PUT /items/{id}` com `available_quantity` / `price` / `status` (`paused`|`active`).
- **Fotos:** `pictures[].source` aceita URL https pública sem redirecionamento (bucket público `produtos` do Supabase); JPG/PNG ≤ 10 MB, mínimo 500×500, recomendado 1200×1200. Fundo branco na 1ª foto **não** é regra da API: fica como lembrete na checagem.
- **Atributos (`GET /categories/MLB6284/attributes`, público):** `GENDER` (339665 feminino, 339666 masculino, 110461 sem gênero), `PERFUME_TYPE` (110465 EDP, 110466 EDT, 209441 parfum, 58874539 elixir, 19463164 body splash, 111075 colônia, 48636309 eau fraîche, 78617106 óleo); `SELLER_PACKAGE_HEIGHT/WIDTH/LENGTH/WEIGHT` aceitam string numérica (cm / g inteiro). Nenhum atributo permite variação → um anúncio por tamanho.

## Review Focus

1. Refresh token de uso único com duas chamadas simultâneas (duas abas, duas funções serverless): uma invalida a outra → a conexão não pode "cair" à toa; quem perdeu a corrida relê o token salvo. (teste na Task 2)
2. Perfume sem `custo_medio` (0) ou sem `volume_ml`: decant não tem custo/ml → o anúncio daquele tipo fica bloqueado com motivo claro, não publica com preço errado. (teste na Task 5)
3. Preço que cruza R$ 79 (frete passa a ser cobrado e a taxa fixa some): o menor preço que fecha a margem pode estar logo abaixo ou logo acima; a busca não pode pular a faixa certa nem ficar em laço. (teste na Task 3)
4. Kit de envio sem peso/medidas com preço ≥ R$ 79: o frete não tem como ser calculado → erro "preencha peso e medidas do Kit de envio" em vez de frete 0. (teste na Task 3)
5. Publicação de 4 anúncios em que o 3º falha (atributo inválido, foto recusada): os outros ficam publicados, o 3º fica `erro` com a mensagem do ML e dá para tentar de novo sem duplicar os já publicados. (teste na Task 7)

### Task 3: Backend — busca do preço (taxas + frete + margem)

**Files:**
- Create: `backend/app/services/anuncios/__init__.py`, `backend/app/services/anuncios/preco.py`
- Test: `backend/tests/test_anuncios_preco.py`

**Interfaces:**
- Produces:
  - `arredondar_90(v: Decimal) -> Decimal` — menor valor terminado em ,90 que seja ≥ `v` (`10.00→10.90`, `10.90→10.90`, `10.91→11.90`).
  - `@dataclass Custos(comissao: Decimal, taxa_fixa: Decimal, frete: Decimal)`
  - `@dataclass Pacote(peso_g: int|None, altura_cm, largura_cm, comprimento_cm)` (Decimal|None)
  - `calcular_preco(custo: Decimal, margem: Decimal, consultar: Callable[[Decimal], Custos]) -> dict` → `{"preco", "comissao", "taxa_fixa", "frete", "lucro"}` (todos Decimal; `lucro = preco − comissao − taxa_fixa − frete − custo`). Lança `ValueError` se `custo <= 0`.
  - `consulta_ml(cliente: MLCliente, listing_type: str, pacote: Pacote) -> Callable[[Decimal], Custos]` — usa `listing_prices` (comissão = `sale_fee_amount − fixed_fee`; taxa fixa = `fixed_fee`) e, só para preço ≥ `FRETE_GRATIS_A_PARTIR = Decimal('79')`, `shipping_options/free` (`list_cost`); abaixo disso frete 0. Guarda as respostas por preço num dicionário local (não repete consulta). Pacote sem peso ou alguma medida com preço ≥ 79 → `ValueError('Preencha peso e medidas do kit de envio')`.
- Algoritmo de `calcular_preco` (o que os testes não determinam sozinhos):
  `alvo = custo × (1 + margem)`; `p = max(arredondar_90(alvo), Decimal('8.90'))`; até 60 voltas: `c = consultar(p)`; `liquido = p − c.comissao − c.taxa_fixa − c.frete`; se `liquido ≥ alvo` → fim; senão `prox = arredondar_90(p + (alvo − liquido))`; se `p < 79.90 < prox`, testar `79.90` antes (a taxa fixa some em R$ 79, então ali pode fechar); `p = prox`. Passou de 60 voltas → `RuntimeError`. `# ponytail: busca por saltos do déficit, não varre centavo a centavo; o ponto 79,90 é o único degrau testado à parte`.
